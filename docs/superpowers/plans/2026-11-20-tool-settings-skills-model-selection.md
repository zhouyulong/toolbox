# 工具配置增强与模型选择修复：概要设计

日期：2026-11-20  
状态：已按本概要设计完成代码实现和本地回归；真实供应商与其他平台原生窗口仍待验证。本文保留设计与验收依据。

## 一、总体方案

在现有结构上完成三项增量改动：**修复模型选择、增加工具级思考强度、增加共享技能库与工具授权**。继续使用现有工具设置、独立工作区和供应商请求链路。本版本仅加入纯文本 Skill，不加入 harness、自动选择 Skill 或多步任务编排。

整体流程保持简单：

**Skill 创建／导入到技能库 → 在工具配置中勾选授权 → 保存工具配置 → 请求时仅加载本工具获授权的 Skill，并附加思考参数 → 调用模型。**

实施顺序：模型选择修复 → 思考强度 → Skill → 联合验收。

## 二、分项设计

### 1. 模型选择修复

**现状：**当前使用文本输入框加原生 `datalist`，并预填第一个模型。代码会填入供应商的全部候选，并不是后端只返回当前模型；具体弹出和过滤行为仍需在桌面窗口复现。

**改法：**替换为“模型下拉列表 + 自定义模型 ID”。

- 点击下拉始终显示当前供应商的全部已配置模型，不受当前值影响。
- 选择“自定义”后，显示模型 ID 输入框，保留手动填写能力。
- 创建工具时显示“请选择模型”，不默认代选第一个。
- 编辑时保留原模型；原模型不在列表中则进入自定义模式。
- 更换供应商后要求重新选择模型，避免错误沿用。

**验收：**配置三个模型后，可直接互相切换；自定义模型可保存；重新打开设置不丢值。

### 2. 每工具思考强度

在工具设置的“请求参数与上下文”中增加：

- **指定思考强度：开／关**，默认关。
- 开启后可选**低／中／高**，初次开启默认中。
- 每个工具独立保存，切换工具不互相影响。

工具定义增加两个可选字段：`sendReasoningEffort` 和 `reasoningEffort`，后者取 `low`、`medium`、`high`。创建、保存、读取和请求组装都接通这两个字段。

请求时，关闭则不发送强度参数；开启则在现有供应商适配中转换为对应参数，具体映射在实施时核对接口文档。不支持的模型或档位明确提示，不静默忽略，也不自动重试。暂不建设模型能力注册表或新增供应商配置页面。

**语义说明：**这里的“关”是使用模型默认行为，不保证关闭模型内部思考；本期不增加思考过程展示。

**验收：**开关与档位保存、重启后不变；检查请求体，关闭时无强度参数，开启时传入所选档位；参数不兼容时能看到明确错误。

### 3. 共享技能库与工具授权

**基本规则：安装与授权分开。Skill 默认安装在应用的统一技能库，每个工具通过自己的配置选择可使用的 Skill。安装成功不等于所有工具自动获得权限。**

#### 版本边界与醒目说明

在技能库页面顶部、新建／导入界面及工具配置的 Skill 选择区，固定显示以下说明，不只放在帮助文档或悬浮提示中：

> **本版本仅支持纯文本 Skill，不支持非纯文本 Skill。** 仅将 Skill 正文作为模型的任务说明使用；不支持依赖脚本执行、本地文件读写、联网检索或外部工具调用的 Skill，也不进行多步任务编排。导入成功不代表其中要求的操作能够执行。

新建 Skill 模板也包含上述版本说明；导入时展示同样提示，不修改外部源文件。正文中的代码仅作为文本，不会运行；不能仅因文件格式为 Markdown 就宣称其任务受支持。

#### 技能库：统一创建和安装

增加“技能库”入口，支持新建、导入、查看、编辑和删除。

- 新建或导入的 `SKILL.md` 统一保存到应用配置目录下的 `skills/<skill-id>/SKILL.md`，不再复制到各工具工作区。
- 每个 Skill 有稳定 ID、名称和正文；多个工具可引用同一份 Skill，无须重复安装。
- 导入采用复制，不修改外部源文件。新安装的 Skill 默认不授予任何工具。
- 编辑共享 Skill 后，所有已授权工具的后续请求使用更新后的内容。
- 删除前检查引用；仍有工具获授权时，提示先取消这些工具的授权，避免留下失效引用。

#### 工具配置：选择可使用的 Skill

在每个工具的配置页面增加“可使用的 Skill”列表，从技能库勾选，可多选。

- 勾选并保存即授权；取消勾选并保存即撤销授权。
- 工具定义只增加 `skillIds` 数组，保存获授权 Skill 的 ID，不保存正文副本。
- 工具 A 的授权与工具 B 独立；两者也可以选择同一个 Skill。
- 取消授权或移除工具，只移除引用，不删除技能库中的文件。
- 授权变更从后续请求生效，不改变已发送的请求，也不删除历史会话。

#### 请求时：按授权范围使用

后端根据工具已保存的 `skillIds` 检查权限，只允许加载清单内的 Skill；不能只靠前端隐藏未授权项目。保存授权时也要验证 ID 确实存在。

本期不先请求 LLM 选择 Skill，也不增加选择后执行的循环；发送前直接将获授权 Skill 的正文与原 System 合成系统指令，交给现有供应商适配；不覆盖原 System，不混入用户历史消息。没有授权时，沿用原来的请求行为。

获授权 Skill 缺失或不可读时，明确报错，不静默跳过。不执行脚本、不自动读取附属资源、不做自动匹配。Skill 内容在请求开始时读取一次，后续编辑不改变已经发出的请求。

**验收：**安装后未授权的工具不能加载；授权后可使用，撤销后新请求不再加载；多个工具共享同一 Skill 时授权互不影响；重启后技能库和授权仍保留；导入源文件始终不受影响。

## 四、实施与验收

1. **模型选择：**先复现并补回归用例，再替换控件，验证选择、自定义及保存。
2. **思考强度：**接通界面、存储与请求，用本地模拟接口检查开关及三档对应的请求参数；真实供应商兼容性单独验证。
3. **Skill：**先完成共享技能库，再完成工具授权与请求接入，验证默认无权限、授权／撤销、多工具共享及后端越权拦截；确认各 Skill 入口有醒目的纯文本限制说明，且不会执行正文中的代码或操作要求。
4. **联合回归：**检查旧工作区读取、重启保存、多轮聊天、流式输出、停止生成及会话导出未受影响。

验收以实际配置、文件和请求结果为准；本规划阶段不宣称功能已完成或测试已通过。
