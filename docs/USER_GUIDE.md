# 使用指南

## 1. 安装与启动

### Windows

解压后双击 `ToolboxSelf.exe`，无需登录。需要 Windows 10/11 和 WebView2 Runtime。若系统缺少运行时，从 Microsoft 官方渠道安装 Evergreen WebView2 Runtime 后再启动。应用没有捆绑一个完整浏览器。

### Linux

安装 GTK 3 和与产物匹配的 WebKitGTK。本项目 CI 使用 Ubuntu 24.04 + WebKitGTK 4.1：

```sh
sudo apt-get update
sudo apt-get install libgtk-3-0t64 libwebkit2gtk-4.1-0
chmod +x ToolboxSelf
./ToolboxSelf
```

也可在文件管理器中赋予执行权限后双击。其他发行版请安装对应库；推荐在目标发行版重新构建，避免 glibc 与 WebKit 不兼容。

### macOS

解压 `.app` 并拖入 Applications，双击打开。当前发布流程不包含开发者证书签名或 notarization；系统可能对下载的未签名应用显示安全提示。确认来源后可通过系统的「隐私与安全性」允许打开；正式公开分发建议配置签名。

双击第二个实例会尝试唤回已有窗口。请不要通过不同用户会话、虚拟机或同步盘让多个实例同时写同一工作区。

## 2. 配置供应商

点击左下角「模型供应商」→「添加供应商」。

| 字段 | 用途 |
| --- | --- |
| 名称 | 自定义显示名，可为同一服务创建不同配置 |
| 接口协议 | OpenAI 兼容、Anthropic Messages、Google Gemini |
| Base URL | 接口前缀，不是完整请求地址 |
| API Key | 供应商密钥；本地免密服务可留空 |
| 模型 ID | 每行一个，必须是供应商实际支持的标识 |
| 超时 | 10–1800 秒，覆盖完整生成时间，默认 180 秒 |

### 接口地址示例

| 服务 | 协议 | Base URL | 应用追加的路径 |
| --- | --- | --- | --- |
| OpenAI 或其兼容服务 | OpenAI 兼容 | `https://api.openai.com/v1` 或对应服务前缀 | `/chat/completions` |
| Anthropic | Anthropic | `https://api.anthropic.com/v1` | `/messages` |
| Gemini | Gemini | `https://generativelanguage.googleapis.com/v1beta` | `/models/<model>:streamGenerateContent?alt=sse` |
| Ollama | OpenAI 兼容 | `http://localhost:11434/v1` | `/chat/completions` |
| LM Studio | OpenAI 兼容 | `http://localhost:1234/v1` | `/chat/completions` |

模型名称会随供应商更新，本应用不内置易过时的固定模型列表。请从自己的控制台、服务文档或本地已加载模型中复制准确 ID。Gemini 可填写纯模型 ID，也接受 `models/` 前缀。

保存已有供应商时，API Key 留空会保留原密钥；填写新密钥则替换；勾选「删除已保存的密钥」会清除。界面不会回显已保存的密钥。供应商仍被工具引用时不能删除。

应用不自动跟随 HTTP 重定向，避免凭据被转发到意外地址；遇到重定向请改用最终接口前缀。后端使用系统环境中的 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`；本地服务通常应通过 `NO_PROXY=localhost,127.0.0.1` 绕过代理。

## 3. 创建工具与定义 system

点击「创建工具」，设置：

1. **名称、说明**：仅在本机展示。
2. **System 提示词**：每次请求携带的工具定义。
3. **供应商、模型 ID**：可从建议列表选择，也可手动输入。
4. **独立工作区**：选择空目录或留空自动创建。
5. **请求参数与上下文**：按模型需求调整。

程序不会预设工具必须做什么，也不会自动执行模型输出。以下只是可自行修改的 system 示例：

```text
你是我的英文写作助手。
我会提供一段英文。请保留原意，修正语法并改善表达。
先给出修改后的文本，再用中文列出关键修改理由。
不要编造事实；含义不清楚时指出歧义。
```

system 在 OpenAI 兼容请求中为 `messages` 中的 `role: system`；Anthropic 为顶层 `system`；Gemini 为 `systemInstruction`。不会通过 user 消息伪装成系统指令。部分特殊模型不接受 system 或使用其他专有协议，需改用支持的模型或兼容网关。

### 工作区规则

- 每个工具有自己的 `toolbox.workspace.json` 和 `chats/`。
- 可分别放在 `D:\WritingTool`、`E:\CodeTool` 或其他位置。
- 默认目录是用户主目录下的 `ToolboxSelf/<随机工具ID>/`，不使用工具名作为路径。
- 不能与全局配置目录重叠，也不能与另一个已登记工具的工作区相同或嵌套。
- 新工具仅接受空目录；已有数据请使用左侧创建按钮旁的「导入工作区」。
- 路径不可直接编辑。需要移动时，停止请求并关闭程序，移动完整目录，再从新位置导入。

## 4. 问答与上下文

Enter 发送，Shift + Enter 换行。每个工具同一时间只允许一个请求；不同工具可各自运行。切换工具不会自动取消请求，左侧小圆点表示正在生成。

提问会先写入会话，再发送网络请求。流式文本实时展示；完成、失败或主动停止后保存助手输出。取消操作取消本地 HTTP 请求，供应商端的计费和停止时机由供应商决定。

### 历史轮数

默认携带最近 **10 个成功的完整问答对**，另加本次问题。设为 0 时只发送 system 和本次问题。失败、输出截断或主动停止的问答会留在界面，但不加入下一次请求上下文。system 始终使用工具当前保存的设置。

历史按轮数截取，不估算 token，也不自动压缩。如果超出模型上下文窗口，请减少历史轮数、缩短文本或新建会话。更换模型或 system 只影响后续请求，现有会话不会清空；希望隔离任务时请新建会话。

### 模型参数

- `temperature` 默认 0.7。模型不支持时关闭「发送 temperature 参数」。Anthropic 等服务可能有更窄的范围，按供应商要求填写。
- 最大输出 token 默认 4096。OpenAI 兼容接口可切换 `max_tokens` 与 `max_completion_tokens`；Anthropic 固定映射 `max_tokens`，Gemini 映射 `maxOutputTokens`。
- 参数上限不等于模型能力上限；应用允许的范围仍需符合所选模型规则。
- 当前不支持 Responses API、工具调用、独立 reasoning 字段展示、多模态或文件附件；不会请求模型执行外部操作。

Markdown 展示支持基础标题、列表、粗体、代码与引用。模型 HTML、远程图片与脚本不会执行或加载；表格和链接以文本保留。单次提问限 4 MiB，单次可显示输出限 32 MiB。

## 5. 会话管理

- 「新建」打开空白会话，首次发送时才创建文件。
- 首次问题自动生成会话标题，可通过右上角「更多」重命名。
- 「导出」通过系统文件对话框保存 `.md`，包含完整问答及错误说明。
- 「删除会话」永久删除对应 JSON 文件，操作前有确认。
- 「工具设置」→「移除登记」只移除侧栏登记，保留全部工作区数据。

## 6. 备份、迁移与更新

### 备份

1. 等待回复结束，或先停止生成，然后退出应用。
2. 复制每个工具的完整工作区目录。
3. 若也要备份供应商配置，单独复制全局 `config.json`。

配置文件包含 API Key 明文，避免提交公共 Git 仓库或分享给他人。Unix 文件与目录使用尽可能收紧的创建权限；Windows 的实际访问权限由用户目录 ACL 决定。应用不使用云同步、系统密钥环或数据库服务。

### 换机或移动目录

1. 将工作区复制到新位置。
2. 在新程序中用「导入工作区」选择包含 `toolbox.workspace.json` 的目录。
3. 配置本机供应商，并在工具设置中重新选择供应商和模型。

供应商以随机 ID 引用。只迁移工作区不会带走密钥；新机器即使创建同名供应商，其 ID 也不同，需要重新绑定。若同时迁移全局配置，旧工作区绝对路径仍需按新机器实际位置重新登记。相同工具 ID 的两个副本不能同时导入。

### 更新

备份后替换可执行文件即可。源码和数据目录分离；卸载程序不会主动删除数据。当前格式版本是 `schemaVersion: 1`。未知版本或损坏文件会报告错误，程序不会自动重置覆盖。未来需要改动格式时应提供显式迁移，见架构文档。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 401/403 | 检查密钥、权限、余额和接口协议 |
| 404 | 检查 Base URL 是否重复加了 `/v1` 或请求路径；确认模型 ID |
| 400 / 不支持参数 | 关闭 temperature，或切换 OpenAI token 参数；检查模型 token 限制 |
| 429 | 等待供应商限流恢复或调整额度；应用不自动重试，避免重复计费 |
| 超时 | 增加超时秒数；检查代理与服务可用性 |
| 流提前结束 | 应用记录已收到文本和错误；检查网关 SSE 支持，再重新提问 |
| 没有可显示文本 | 可能仅返回 reasoning、工具调用、内容过滤或耗尽推理 token；改用文本模型或增加限额 |
| 工作区无法读取 | 检查移动磁盘、路径与文件权限；目录移动后移除旧登记并重新导入 |
| 初始化失败 | 备份全局配置，检查 JSON 格式和 schemaVersion；不要盲目清空数据 |
| 会话列表报错 | 查看错误中的会话 ID；退出程序后备份该 JSON，修复或将损坏文件移出 `chats/` |
| Windows 启动失败 | 安装 WebView2 Runtime；使用从可信源码构建的产物 |
| Linux 缺少共享库 | 安装匹配的 GTK/WebKitGTK，或在目标发行版重新构建 |

详细错误不会写入常驻日志。HTTP 错误会展示截断后的供应商响应，并替换当前配置中出现的 API Key；导出错误信息前仍应检查供应商可能返回的其他敏感内容。
